Works with any standard OIDC provider (Authelia, Keycloak, Authentik, ...) — Wharf only ever speaks the discovery + authorization code protocol, nothing provider-specific. With no groups configured below, anyone who can authenticate against this provider gets a Wharf account automatically, as operator. Promote or demote any account from the Users page.

Checked against the provider's groups claim on every sign-in, not just the first — a member of Admin group becomes/stays admin, a member of Operator group becomes/stays operator. Setting either one turns sign-in itself into an allowlist: once one of these is configured, only members of that group (or both, if both are set) can sign in at all — everyone else is refused, not silently given an operator seat. Leave both blank to keep the original behavior (anyone who authenticates gets in as operator, roles only ever change manually via Users). Your provider must be configured to send a groups claim, and its client registration must permit the groups scope (verified against Authelia: add groups to that client's scopes, backed by an AD/LDAP group lookup).

Real lockout risk: once this is on, /login only offers "Continue with {{.OIDC.DisplayName}}" — every existing local account (including yours) stops working, and there is no built-in way back in if the provider becomes unreachable or misconfigured afterward. Recovering from that requires direct access to the controller's database. Make sure SSO works end to end, for an account you can actually get into, before turning this on.

Register Wharf as a client on the provider first (issuer, client ID/secret, and the redirect URI above), then paste its details here.
