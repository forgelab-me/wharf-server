Secret providers

External services a Git stack's secrets.refs.yaml can read from — a reference like ref+vault://secret/blog/db#/password is resolved by the controller at deploy time, using the connection attached to that stack. A connection holds the address and, optionally, default credentials; each stack still chooses which paths it may read, and can use credentials of its own. ref+sops:// needs no connection.

Bitwarden tool

Bitwarden Secrets Manager is read through Bitwarden's own command-line tool, bws {{.Version}}. Its licence does not allow Wharf to ship it, so the controller downloads it from Bitwarden's release page when you ask, checks it against a pinned checksum, and keeps it in the cache volume. Nothing is downloaded until you do.
